- `b'\xff\xff\xff\n'` contains three `FF` bytes followed by a newline.
- `|` pipes the generated bytes into Netcat.
- `nc` connects to the remote challenge service.

The newline was included because the application used `readline()` to receive input.

## Key Concepts

### Hexadecimal Bytes

Hexadecimal is a base-16 numbering system commonly used to represent individual bytes.

A byte can have values ranging from `00` to `FF`.

In this challenge, `FF` represents the maximum value of a single byte (255 in decimal).

### Python Bytes

Python distinguishes between strings and bytes.

For example:

    "hello"

represents a string, while:

    b"hello"

represents a byte sequence.

A hexadecimal byte can be represented using an escape sequence:

    b"\xff"

Three consecutive `FF` bytes are represented as:

    b"\xff\xff\xff"

### Standard Input and Output

Programs commonly receive input through standard input (`stdin`) and send output through standard output (`stdout`).

Python provides binary access through:

    sys.stdin.buffer
    sys.stdout.buffer

These interfaces allow programs to receive and transmit raw bytes without treating them as ordinary text.

### Netcat and Pipes

Netcat (`nc`) is a networking utility that allows communication with remote services.

A pipe (`|`) connects the output of one command to the input of another.

Combining Python and Netcat made it possible to generate and transmit binary data that could not be entered correctly as ordinary terminal text.

## Lessons Learned

- Always inspect the source code to understand exactly what input a program expects.
- Hexadecimal representations are not the same as actual binary bytes.
- Typing `0xFF` does not transmit the byte `FF`.
- Python's `sys.stdout.buffer.write()` is useful when working with raw binary data.
- Pipes allow one program to generate data and another program to transmit it.
- When a challenge expects binary input, consider generating the bytes programmatically instead of typing them manually.
